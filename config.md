## Root configuration object

| Name | Type | Description | |
| --- | --- | --- | --- |
| <a id="config-opt-server-bind"></a>`server.bind` | string | Address to bind the API server to<br>Defaults to all interfaces because the service is meant to run in a container, where the port is published rather than reached over loopback<br>Set to "127.0.0.1" to only accept connections from the same host| Default: _"0.0.0.0"_ |
| <a id="config-opt-server-port"></a>`server.port` | number | Port for the API server to listen on| Default: _3000_ |
| <a id="config-opt-server-publicurl"></a>`server.publicUrl` | string | Public origin of this service<br>It's the default audience of the JWTs this service accepts| Default: _"http://127.0.0.1:3000"_ |
| <a id="config-opt-server-corsallowedorigins"></a>`server.corsAllowedOrigins` | list of strings | Origins browsers may call `/v1/public/*` from, for example `https://app.example.com`<br>Only the public routes answer cross-origin requests; the client API never does|  |
| <a id="config-opt-server-trustedproxies"></a>`server.trustedProxies` | list of strings | IP addresses or CIDRs of the reverse proxies in front of this service, such as a load balancer or an ingress controller<br>A request from one of them is logged and traced with the client address its X-Forwarded-For, Forwarded or X-Real-IP header names, and those headers are dropped from any other request, so a client can't make up its own address|  |
| <a id="config-opt-server-readtimeout"></a>`server.readTimeout` | duration | Maximum time to read a whole request, including its body<br>It bounds how long a slow client can hold an upload open, so it has to leave room for the largest upload over the slowest link you accept| Default: _"5m"_ |
| <a id="config-opt-server-writetimeout"></a>`server.writeTimeout` | duration | Maximum time to write a response, measured from the end of reading the request headers| Default: _"5m"_ |
| <a id="config-opt-server-tls-path"></a>`server.tls.path` | string | Path where to load TLS certificates from<br>Within the folder, the files must be named `tls-cert.pem` and `tls-key.pem`. The application watches for changes in this folder and automatically reloads the TLS certificates when they're updated.<br>If empty, certificates are loaded from the same folder where the loaded `config.yaml` is located, when both files are there.<br>Startup fails when a folder named here doesn't contain both files, or when either folder contains only one of them.| Default: _the same folder as the `config.yaml` file_ |
| <a id="config-opt-server-tls-certpem"></a>`server.tls.certPEM` | string | Full, PEM-encoded TLS certificate<br>Using `certPEM` and `keyPEM` is an alternative method of passing TLS certificates than using `path`, and the two must be set together.|  |
| <a id="config-opt-server-tls-keypem"></a>`server.tls.keyPEM` | string | Full, PEM-encoded TLS key<br>Using `certPEM` and `keyPEM` is an alternative method of passing TLS certificates than using `path`, and the two must be set together.|  |
| <a id="config-opt-auth-jwt-issuer"></a>`auth.jwt.issuer` | string | Issuer whose tokens are accepted, which must match their `iss` claim<br>When `jwksUrl` is empty, the key set is discovered from `<issuer>/.well-known/openid-configuration`<br>JWT authentication is disabled when this is empty|  |
| <a id="config-opt-auth-jwt-audience"></a>`auth.jwt.audience` | string | Expected `aud` claim, which is this service's identifier at the provider<br>If empty, `server.publicUrl` is used|  |
| <a id="config-opt-auth-jwt-jwksurl"></a>`auth.jwt.jwksUrl` | string | URL of the issuer's JWKS, for providers that don't publish OpenID Connect discovery<br>A key set found through discovery must be on the issuer's origin, but one named here is trusted as the operator configured it|  |
| <a id="config-opt-auth-jwt-subjectclaim"></a>`auth.jwt.subjectClaim` | string | Claim that holds the caller's subject| Default: _"sub"_ |
| <a id="config-opt-auth-jwt-scopeclaim"></a>`auth.jwt.scopeClaim` | string | Claim that holds the caller's scopes, either as a space-separated string or as an array| Default: _"scope"_ |
| <a id="config-opt-auth-apikeys"></a>`auth.apiKeys` | list | API keys accepted in the `Authorization: Bearer` header<br>Each entry has an `id`, exactly one of `key` (the key itself, which must start with `pvk_`) and `sha256` (the hex-encoded SHA-256 of the key), the `subject` the key authenticates as (defaulting to the `id`), and the `scopes` it grants|  |
| <a id="config-opt-auth-scopes-ingest"></a>`auth.scopes.ingest` | string | Scope required to upload through `/v1/public/ingest` and read the status of one's own jobs<br>Set it to an empty string to accept any authenticated caller| Default: _"ingest"_ |
| <a id="config-opt-auth-scopes-server"></a>`auth.scopes.server` | string | Scope required to use the client API under `/v1/client`, which is trusted with every namespace<br>Set it to an empty string to accept any authenticated caller| Default: _"server"_ |
| <a id="config-opt-auth-none-enabled"></a>`auth.none.enabled` | boolean | If true, every request is accepted as `subject` with `scopes`, without checking any credentials<br>It can't be combined with `jwt` or `apiKeys`, and it's meant for development only|  |
| <a id="config-opt-auth-none-subject"></a>`auth.none.subject` | string | Subject every request is accepted as| Default: _"anonymous"_ |
| <a id="config-opt-auth-none-scopes"></a>`auth.none.scopes` | list of strings | Scopes every request is granted| Default: _["ingest", "server"]_ |
| <a id="config-opt-authorizer-type"></a>`authorizer.type` | string | Kind of authorizer: `http` or `static`<br>If empty, browser uploads are disabled|  |
| <a id="config-opt-authorizer-http-url"></a>`authorizer.http.url` | string | URL the authorization request is posted to|  |
| <a id="config-opt-authorizer-http-timeout"></a>`authorizer.http.timeout` | duration | Maximum time to wait for the authorizer's answer| Default: _"10s"_ |
| <a id="config-opt-authorizer-http-auth-type"></a>`authorizer.http.auth.type` | string | How the request authenticates: `hmac` and `ed25519` sign it following the Standard Webhooks specification, `oauth2` sends a client-credentials bearer token, and `none` sends nothing|  |
| <a id="config-opt-authorizer-http-auth-hmac-secrets"></a>`authorizer.http.auth.hmac.secrets` | list of strings | Secrets the requests are signed with, in the Standard Webhooks `whsec_` form<br>Every secret signs, so the receiver can rotate by adding the new secret here before removing the old one|  |
| <a id="config-opt-authorizer-http-auth-oauth2-tokenurl"></a>`authorizer.http.auth.oauth2.tokenUrl` | string | Token endpoint of the identity provider|  |
| <a id="config-opt-authorizer-http-auth-oauth2-clientid"></a>`authorizer.http.auth.oauth2.clientId` | string | Client ID of this service at the provider|  |
| <a id="config-opt-authorizer-http-auth-oauth2-clientsecret"></a>`authorizer.http.auth.oauth2.clientSecret` | string | Client secret, as an alternative to `clientAssertion`|  |
| <a id="config-opt-authorizer-http-auth-oauth2-clientassertion"></a>`authorizer.http.auth.oauth2.clientAssertion` | string | Federated credential to authenticate with instead of a client secret, per RFC 7523 section 2.2<br>Supported values: `AzureManagedIdentity`, `AzureManagedIdentity=<client-id>`, `AzureWorkloadIdentity`, `KubernetesServiceAccountToken`, `KubernetesServiceAccountToken=<path>`, `tsiam=<endpoint>`|  |
| <a id="config-opt-authorizer-http-auth-oauth2-clientassertionaudience"></a>`authorizer.http.auth.oauth2.clientAssertionAudience` | string | Resource requested from tsiam, required when `clientAssertion` uses tsiam|  |
| <a id="config-opt-authorizer-http-auth-oauth2-scopes"></a>`authorizer.http.auth.oauth2.scopes` | list of strings | Scopes requested for the token|  |
| <a id="config-opt-authorizer-http-auth-oauth2-endpointparams"></a>`authorizer.http.auth.oauth2.endpointParams` | map | Extra parameters sent to the token endpoint, such as `audience` for providers that need one|  |
| <a id="config-opt-authorizer-http-auth-allowunauthenticated"></a>`authorizer.http.auth.allowUnauthenticated` | boolean | Must be true for `type` to be `none`, as an explicit acknowledgement that the receiver can't tell these requests from forged ones|  |
| <a id="config-opt-authorizer-static-namespace"></a>`authorizer.static.namespace` | string | Namespace every upload is stored in|  |
| <a id="config-opt-authorizer-static-maxbytes"></a>`authorizer.static.maxBytes` | int64 | Maximum size of an upload in bytes, applied together with `images.maxUploadSize`|  |
| <a id="config-opt-authorizer-static-allowedformats"></a>`authorizer.static.allowedFormats` | list of strings | Source formats uploads may be in: `jpg` (or `jpeg`), `png`, `webp`, `avif`, `heic`, `heif`<br>If empty, every supported format is allowed|  |
| <a id="config-opt-authorizer-static-variants"></a>`authorizer.static.variants` | list | Variants to generate for every upload, each with `format`, `quality`, optional `effort`, `size` (`width` and `height`), and optional `fit`|  |
| <a id="config-opt-authorizer-static-notify-endpoint"></a>`authorizer.static.notify.endpoint` | string | Name of the endpoint in `notify.endpoints`, or empty for the default one|  |
| <a id="config-opt-authorizer-static-notify-context"></a>`authorizer.static.notify.context` | map | Object echoed back in every event|  |
| <a id="config-opt-notify-defaultendpoint"></a>`notify.defaultEndpoint` | string | Endpoint used when a request asks for a notification without naming one<br>If empty and exactly one endpoint is configured, that one is used|  |
| <a id="config-opt-notify-endpoints"></a>`notify.endpoints` | map | Webhook endpoints by name<br>Each one has a `url`, an optional `timeout` (default `15s`), and the `auth` its requests carry, with the same options as `authorizer.http.auth`|  |
| <a id="config-opt-signing-ed25519-activekey"></a>`signing.ed25519.activeKey` | string | ID of the key requests are signed with, which must have a private key|  |
| <a id="config-opt-signing-ed25519-keys"></a>`signing.ed25519.keys` | list | Signing keys<br>Each one has an `id` and either a private key (`privateKey`, or `privateKeyFile` for a path) or, for a retired key that is still published, a public key (`publicKey` or `publicKeyFile`)<br>Keys are PEM-encoded, or in the Standard Webhooks `whsk_` and `whpk_` forms|  |
| <a id="config-opt-images-maxuploadsize"></a>`images.maxUploadSize` | int64 | Maximum size of an uploaded image, in bytes| Default: _33554432 (32 MB)_ |
| <a id="config-opt-images-maxsourcepixels"></a>`images.maxSourcePixels` | int64 | Maximum number of pixels in an uploaded image, after its EXIF orientation is applied<br>It bounds the memory decoding an image can take, whatever its size in bytes: at the default, one encode takes up to about 1 GB| Default: _50_000_000_ |
| <a id="config-opt-images-maxvariants"></a>`images.maxVariants` | number | Maximum number of variants a single job can ask for<br>A request names every variant an image needs, including the ones it already has| Default: _48_ |
| <a id="config-opt-images-maxresolution"></a>`images.maxResolution` | number | Maximum width or height, in pixels, of a requested variant| Default: _8192_ |
| <a id="config-opt-images-maxqueuedjobs"></a>`images.maxQueuedJobs` | number | Maximum number of jobs that can wait for one image while another of its jobs runs| Default: _10_ |
| <a id="config-opt-images-maxconcurrentencodes"></a>`images.maxConcurrentEncodes` | number | Maximum number of encoding tasks Francis runs on each host at once.<br>Encoding is CPU- and memory-bound, so this bounds the resources a burst of jobs can consume while allowing excess tasks to move to another host.<br>Variants are encoded one per thread, so this is the only concurrency knob: libvips itself is configured to use a single thread per operation.<br>Each encode takes up to about 1 GB of memory for a source of 50 megapixels (the default "images.maxSourcePixels"), and that scales with the pixel count, so the memory available should be at least this many times that.<br>If empty, defaults to the number of CPUs the process can use, which follows the CPU limit of a container.|  |
| <a id="config-opt-images-vipscachemaxmemory"></a>`images.vipsCacheMaxMemory` | number | Maximum amount of memory, in bytes, libvips uses for its operation cache| Default: _52428800 (50MB)_ |
| <a id="config-opt-storage-originals"></a>`storage.originals` | string | Where the uploaded source images are stored<br>Local file system: `fs:/path/to/folder`, `local:/path/to/folder`, or a path with no protocol at all<br>A local folder can end with `?fileMode=0644&dirMode=0755` to set the permissions of the files and folders it gets, which default to `0600` and `0750`<br>S3: `s3://<access-key>:<secret-key>@s3.<region>.amazonaws.com/<bucket>?prefix=<key-prefix>&sessionToken=<token>`<br>Vercel Blob with a read-write token: `vercelblob:?tokenEnv=<environment-variable>&access=private&prefix=<key-prefix>`<br>Vercel Blob with OIDC: `vercelblob:?auth=oidc&storeIdEnv=<environment-variable>&access=private&prefix=<key-prefix>`| Default: _"./data/originals"_ |
| <a id="config-opt-storage-variants"></a>`storage.variants` | string | Where the generated variants and the manifests are stored, using the same connection strings as `originals`| Default: _"./data/variants"_ |
| <a id="config-opt-storage-sourcecache"></a>`storage.sourceCache` | string | Folder on the local file system the source images are cached in while their variants are generated<br>Every variant of an image is encoded from the same source, so each job downloads it once into this folder and every step that follows reads it from there<br>A job deletes its file when it terminates, and the ones a host left behind by stopping in the middle of a job are swept once they are older than twice `actors.workflowTimeout`<br>Unlike `originals` and `variants` this is a path rather than a connection string, because it is never anything but a local folder<br>It holds only files that can be downloaded again, so it belongs on ephemeral storage: in a container that is a writable `/tmp`| Default: _a folder inside the system temporary directory_ |
| <a id="config-opt-ratelimit-rate"></a>`rateLimit.rate` | number | Number of uploads admitted per caller during each `per` interval| Default: _10_ |
| <a id="config-opt-ratelimit-per"></a>`rateLimit.per` | duration | Interval over which `rate` uploads are admitted| Default: _"1m"_ |
| <a id="config-opt-ratelimit-burst"></a>`rateLimit.burst` | number | Maximum number of uploads from one caller that can be admitted at once before throttling starts<br>It's what lets a user drop a whole folder of photos in at once, while `rate` bounds a steady stream| Default: _30_ |
| <a id="config-opt-actors-runtime"></a>`actors.runtime` | string | How the actor runtime this service uses is provided. Supported values: `embedded` (default), `external`<br>With `embedded` the runtime runs inside this process and persists to `actors.database`, so there's nothing else to deploy<br>With `external` this process is only an actor host, and it connects to a standalone Francis runtime configured under `actors.external`, which owns the database instead| Default: _"embedded"_ |
| <a id="config-opt-actors-address"></a>`actors.address` | string | Address (`host:port`) at which this actor host can be reached by its peers<br>In a single-instance deployment this only needs to be an address the process itself can bind to<br>The `PROVINO_ACTORS_ADDRESS` environment variable overrides it, which is how instances that share one configuration file each advertise their own address| Default: _"127.0.0.1:7571"_ |
| <a id="config-opt-actors-bindaddress"></a>`actors.bindAddress` | string | Address to bind the actor host's peer server to<br>If empty, the host part of `address` is used|  |
| <a id="config-opt-actors-bindport"></a>`actors.bindPort` | number | Port to bind the actor host's peer server to<br>If empty, the port part of `address` is used|  |
| <a id="config-opt-actors-database"></a>`actors.database` | string | Database the embedded actor runtime persists actor state to, as a connection string<br>SQLite: `sqlite://<path-to-file>`, or a path with no protocol at all<br>Postgres: `postgres://<user>:<password>@<host>:<port>/<database>`, optionally with connection options (`postgresql://` is an alias). Required to run more than one instance against the same jobs<br>Ignored when `actors.runtime` is `external`, since the standalone runtime owns the database in that case| Default: _"sqlite://./data/actors.db"_ |
| <a id="config-opt-actors-runtimepsk"></a>`actors.runtimePSK` | string | Pre-shared key the cluster CA is derived from: actor hosts that share the same key authenticate each other with mTLS.<br>Recommended to generate with `openssl rand -base64 32`<br>If empty, a random key is generated at startup, which is only usable when running a single instance<br>Only used when `actors.runtime` is `embedded`: with an external runtime the cluster CA comes from the runtime itself|  |
| <a id="config-opt-actors-external-addresses"></a>`actors.external.addresses` | list of strings | Addresses (`host:port`) of the runtime replicas this host connects to.<br>The host connects to one at a time and rolls over to another when it fails.<br>Required when `actors.runtime` is `external`.|  |
| <a id="config-opt-actors-external-bootstrappsk"></a>`actors.external.bootstrapPSK` | string | Pre-shared key this host authenticates to the runtime with.<br>Exactly one of `bootstrapPSK` and `bootstrapTokenFile` is required when `actors.runtime` is `external`.|  |
| <a id="config-opt-actors-external-bootstraptokenfile"></a>`actors.external.bootstrapTokenFile` | string | Path of a file containing the JWT this host authenticates to the runtime with.<br>The file is re-read on every bootstrap, so a rotated token (such as a Kubernetes projected service account token) is picked up.|  |
| <a id="config-opt-actors-external-capath"></a>`actors.external.caPath` | string | Path of a file containing the PEM-encoded cluster CA certificates this host trusts before its first connection to the runtime.<br>With the CA pinned, the host can verify the runtime from the very first connection.|  |
| <a id="config-opt-actors-external-capem"></a>`actors.external.caPEM` | string | PEM-encoded cluster CA certificates, as an alternative to `caPath`.|  |
| <a id="config-opt-actors-external-unsafenopinnedca"></a>`actors.external.unsafeNoPinnedCA` | boolean | If true, the host trusts the runtime's certificate on the first connection instead of pinning the cluster CA.<br>This is unsafe: anyone able to intercept that first connection can impersonate the runtime, which also exposes the bootstrap token when authenticating with a JWT.<br>Exactly one of the CA options and this one must be set when `actors.runtime` is `external`.|  |
| <a id="config-opt-actors-workflowtimeout"></a>`actors.workflowTimeout` | duration | How long each workflow handler attempt and compensation may execute after a worker starts it<br>Queue wait and retry backoff do not consume this execution budget<br>The complete workflow has a separate backstop of six times this value, which starts when the job leaves the image's queue| Default: _"10m"_ |
| <a id="config-opt-actors-completedworkflowretention"></a>`actors.completedWorkflowRetention` | duration | How long the status of a finished job is retained before it expires.<br>Set to 0 to retain it indefinitely.| Default: _"24h"_ |
| <a id="config-opt-logs-level"></a>`logs.level` | string | Controls log level and verbosity. Supported values: `debug`, `info` (default), `warn`, `error`| Default: _"info"_ |
| <a id="config-opt-logs-omithealthchecks"></a>`logs.omitHealthChecks` | boolean | If true, calls to the health check endpoints (`/healthz` and `/readyz`) are not included in the logs| Default: _true_ |
| <a id="config-opt-logs-json"></a>`logs.json` | boolean | If true, emits logs formatted as JSON, otherwise uses a text-based structured log format.<br>Defaults to false if a TTY is attached (e.g. when running the binary directly in the terminal or in development); true otherwise.|  |
